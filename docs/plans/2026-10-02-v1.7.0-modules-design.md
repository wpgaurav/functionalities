# Functionalities 1.7.0 modules

Approved scope: Content Tools, Link Health, and Site Activity. Implementation and snapshot-backed Gatilab testing are authorized. Public release is a separate step.

All modules remain disabled by default. They use the existing registry and module options; no new services, accounts, credentials, database tables, or frontend assets are required. Minimum WordPress 6.3 / PHP 7.4 remains unchanged.

## Content Tools

Posts/pages gain a permission-checked Duplicate as draft action. Preserve stored block content, excerpt, supported taxonomies, featured image, and page template. Use a developer metadata allowlist; exclude edit locks, history, plugin scan metadata, comments, revisions, source author, slug, password, and publication status. The current user owns the draft. Roll back the draft on taxonomy/metadata failure. Check edit_post, destination create_posts, taxonomy assignment, and the action nonce.

## Link Health

Scan anchor URLs in stored public, published posts/pages, excluding password-protected content. Dynamic blocks, shortcodes, navigation, and rendered-only links are outside this version's coverage. Use the core HTML tag processor without rewriting content. Resolve relative links against the source permalink, deduplicate normalized URLs, reject credentials/private hosts and unsupported protocols, and use safe HEAD requests with bounded GET confirmation/fallback. 404/410 are broken only after GET confirmation; auth errors, throttling, transport failures, and 5xx are inconclusive.

Keep per-post results in postmeta, deduplicated URL checks in expiring transients, and a protected JSON scan cursor with an expiring worker lease. A bounded batch resumes inside a large post, uses an ID cursor, and is safe against overlapping workers. Each post is limited to 1,000 unique URLs and reports truncation explicitly. Report pages contain one source post and at most 50 visible links; CSV export streams every source report. A content hash prevents publishing stale results after an edit. Manual start/resume, ignore/recheck per result, paginated reports, CSV export, and opt-in weekly scans are admin-only. Cron is visit-driven; manual resume is available. Retain results on disable; clear scheduled work. Uninstall honors the existing deletion preference.

## Site Activity

Log module-setting field names, plugin/theme activation/update, and post/page status transitions. Store actor ID, event, target, timestamp, and allowlisted status/field details only. Never store secrets, code bodies, full content, request data, visitor IPs, or authentication attempts. Protected atomic JSON storage retains at most 1,000 entries / 30 days. Include filtering/search, pagination, explicit clear, daily pruning, and user-erasure/deletion anonymization. Failure to log must not block the underlying operation.

## Verification and rollout

Each module is independently usable. Test positive and negative permissions, disabled loading, failures, bounded scans, safe HTTP redirects/private URLs, duplicate cache reuse, content-edit races, leases/resume, CSV escaping, retention, concurrent storage writes, privacy, import sanitization, and uninstall. Run composer check, npm test, real-core HTML API tests, translation freshness, and package validation. Snapshot Gatilab plugin/settings/content, install the verified candidate, exercise actions with disposable content, verify readback and public storage guards, then remove fixtures and restore module settings. Retain a plugin rollback archive and a verification report.
